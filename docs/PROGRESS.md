## 1. Summary

Reqo is a memecoin launchpad on QoreChain testnet (Diana). Users create tokens from a web page, and the factory records each token and its creator.

- **v1** (Solidity, deployed): only the account holding an open EVM window can create tokens, so creation works for the owner account only.
- **v2** (Solidity, deployed and tested): users sign a creation request off chain, and a relayer submits it. The signer is recorded as creator, so users need no window. Supply uses 18 decimals.

The frontend still points at the v1 factory. Updating it to v2 is the next frontend step.

**Functions:**
- `createToken(name, symbol, supply, description)`: direct path. Sender is creator and needs the sender's own window.
- `createTokenFor(CreateRequest r, bytes signature)`: relayed path. The signer must equal `r.creator`.
- `digest(CreateRequest r)`: returns the EIP-712 digest for the frontend.
- `tokenCount()`, `tokens(i)`, `creatorOf(token)`, `nonceUsed(creator, nonce)`.
- Constants: `DECIMALS` 1e18, `MAX_WHOLE_SUPPLY` 1e12, `MAX_DESCRIPTION` 280, `CREATE_TYPEHASH`.
- EIP-712 domain: name "Reqo MemeFactory", version "2", chainId 9800, verifyingContract = factory address.

**Checks in code:** name 1 to 32 chars ("bad name"), symbol 1 to 10 chars ("bad symbol"), supply greater than 0 ("zero supply"), supply at most 1e12 whole tokens ("supply too large"), description at most 280 chars ("bad description"), deadline not passed ("expired"), nonce not used ("nonce used"), signer equals creator ("bad signature").

**Known limits (v2):**
- Anyone with gas can submit a valid signed request. The relayer pays gas and the signer owns the token.
- No creator fee, launch parameters, trading, or liquidity. These belong to later versions.
- Not audited.

## 6. EVM Authorization Window (verified behaviour)

- A window is per account. It only permits transactions from that account.
- Opened from the Dashboard or QoreX, on an Ethereum (coin type 60) account. A standard qor1 (coin type 118) account cannot sign for its EVM address.
- Requires a registered ML-DSA-87 key. Registration and open/close use the PQ key. Transactions inside the window are signed by the normal EVM key.
- Query: `GET https://api-testnet.qore.host/qorechain/pqc/v1/evm_window/<qor1 address>`. Use the qor1 address, not the 0x address. Fields checked: `live`, `remaining_blocks`, `remaining_txs`.
- Limits observed: `blocks` up to 17,280 (about 6 hours on testnet), `max_txs` up to 1,000, `max_value` in uqor (counts value plus max fee). `native_only` false allows contract creation.
- Windows used for contract creation must not set `allowed-targets`, since contract creation is refused under a scope.
- Windows expire on their own. There is no permanent window.
- **Observed:** window expiry during use produced the frontend error "could not coalesce error".
- **Verified in v2 testing:** a relayed `createTokenFor` succeeded using the owner's window, with a signer that has no window and no funds.

## 11. Release Format

Each update follows this block, and each release adds an entry to the changelog in the same commit.

- **Version:** vX.Y.Z (patch for fixes, minor for features, major for contract changes)
- **File:** `reqo-vX.Y.Z.html` for the page, or `reqo-vX.Y.Z-contracts.md` for contract notes
- **Change:** one line
- **Commit:** `vX.Y.Z: short description`
- **Checks before push:** version string present in the file, diff size matches the change, no content from other projects
- **Checks after deploy:** version string present on the live page
- **Docs:** this file is updated in the same commit, sections 5, 6, 8, 9, and 10 as relevant
